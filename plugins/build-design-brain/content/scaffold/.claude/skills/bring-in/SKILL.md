# Bring something in

Follow `CLAUDE.md`'s rules throughout, "When the designer edits a page" first, and its "Design rules". "The owner" below is the designer. One source often touches several pages.

1. **Get the material into the brain, as it came.** If the owner says where a file is (Desktop, Downloads), read it there and copy it as it is into `inbox/`; a file already in `inbox/` stays exactly as it is. Something the owner types is saved as typed, to `inbox/YYYY-MM-DD-<topic>.md`; a change to something the brain says is saved as `inbox/YYYY-MM-DD-change.md` (`-change-2.md` for a second that day) and logged `filed (change)`. If you can't read a file's format directly (a Word file), save a text copy beside it with the same name plus `.md` (`2026-11-17-proposal.docx.md`; on a Mac, `textutil -convert txt -output <copy> <file>`), read that, and cite the original. If no text copy can be made, ask the owner to type its key lines. Never change a file that came in.
2. **Check what it holds before filing anything.** Research or feedback that names or points to a participant or customer doesn't come in: say why, and ask for an anonymised version (participants by code). Anything the designer's employer hasn't cleared doesn't come in. Screenshots or frames showing a real customer's data don't come in until cropped or blurred. Something the designer might not want quoted goes to `private/`, with their yes. A Figma link is read through the connector (outline first, only what's needed), and each read is saved to `sources/figma/YYYY-MM-DD-<what>.md`, as it came, before it's cited.
3. **Find what it touches:** read `index.md`, search the files, and read the pages it bears on.
4. **Draft from it only what it states** (`CLAUDE.md`, "Drafting from material"), routed as the design rules say: the library to `design-system/DESIGN.md` and component pages; a flow's frames or screenshots to its flow page; screenshots of the shipped product to `sources/screens/`; anonymised notes to a study and one draft finding per observation (`research/findings/F-<nnn>.md`, the next free number); what someone decided to a decision. Every gap, disagreement and value you can't read is `[ASK]`, none filled or chosen by you.
5. **Show the plan,** one line per change: page, what changes, the source, and whether you write it or the owner approves it (`CLAUDE.md`, "What you write and what the designer approves").
6. **Write the changes you make alone** without waiting: notes, timeline entries, new `draft` pages.
7. **Bring back the rest, one at a time:** say the change and its source in a line, then write it, so Claude Code asks the owner. On a "no", ask what's true instead, and save the answer as typed in `inbox/` (filed with this material).
8. **Where the new contradicts the old:** follow `CLAUDE.md`'s design rule on disagreeing sources. Show both versions with their sources, and ask which wins; never decide a conflict on a root file, a `verified` page or a decision yourself.
9. **A decision:** write `decisions/YYYY-MM-DD-<slug>.md` with **Decided by** (the designer, or someone else by role), **Context**, **Options considered**, **Decision**, **Why**, **Evidence** (each line with its source), **What would reverse it** and **Affects** (the flows and components), the why and the reversal in the designer's words (ask for them; never word them). Link it from the pages it affects, and on each flow page it affects, add a timeline entry, and a sourced summary change, saying how the decision changes the flow, in the designer's words (ask; never word it). If it replaces an earlier decision, add `supersedes:` and, with the designer's yes, change only the old one's `status` to `superseded`.
10. **Finish:** move each file this filing brought in, with its text copy, from `inbox/` to `sources/` (to `private/` if the designer asked), as it is: only once everything it states is filed; a file you couldn't file stays in `inbox/`, and you say why. Make sure every citation points at the file's new place. Update `index.md`, add to `log.md` one line per filing (`filed <sources or private file> → <every page it touched>`, with `(approved)` on what the owner said yes to), and commit if this folder uses git. If the material is a correction to a fact (the owner fixing what a piece of work got wrong), also log `correction → <page>: "<the rule's first words>"`. Then say in two lines what changed.
